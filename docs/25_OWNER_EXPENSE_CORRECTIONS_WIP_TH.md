# การแก้ค่าใช้จ่ายโดยเจ้าของผ่าน LINE — งานระหว่างพัฒนา

**ยังไม่เปิดใช้งานจริง:** ฟีเจอร์อยู่ใน PR #222 และปิดไว้โดยปริยาย เอกสารนี้อธิบายพฤติกรรมที่กำลังพัฒนา ไม่ใช่คู่มือสำหรับสั่งงานระบบ Production ปัจจุบัน

หลังผ่านเกณฑ์เปิดใช้ เจ้าของที่ยืนยันตัวตนแล้วจะพิมพ์ `แก้ไขค่าใช้จ่าย` เพื่อค้นจากชื่อร้าน วันที่ หรือยอด เลือกรายการและช่องที่ต้องการแก้ แล้วตรวจค่าเดิมเทียบค่าใหม่ก่อนยืนยัน รายการที่ยังไม่ยืนยันต้องผ่านขั้นตอนยืนยันรายละเอียด หมวดหมู่ และช่องทางชำระเดิมต่อไป

เจ้าของจะพิมพ์ `สถานะการแก้ไข` เพื่อดูรายการที่กำลังซิงก์ ซิงก์แล้ว หรือรอตรวจ และพิมพ์ `รายการแก้ไขรอตรวจ` เพื่อดูคำขอที่ยังไม่เปลี่ยนข้อมูล หลังติดตั้งตารางที่จำเป็นแล้ว คำสั่งดูสถานะยังทำงานเมื่อพักการรับคำแก้ใหม่ แต่ปุ่มที่เปลี่ยนข้อมูลจะตอบว่าพักใช้งาน หากเปิดรับคำแก้และแก้สาเหตุที่ค้างแล้ว สามารถเลือกตรวจอีกครั้ง ระบบจะสร้างร่างใหม่และให้เจ้าของยืนยันใหม่ ไม่ใช้การกดซ้ำเป็นคำสั่งบันทึกโดยอัตโนมัติ

## การตรวจงานค้างสำหรับผู้ดูแล

- เมื่อเปิดฟีเจอร์แล้ว `GET /admin/owner-correction/review-summary` แสดงจำนวนคำขอรอตรวจแยกเหตุผล
- `GET /admin/owner-correction/review-queue?kind=manual` และ `kind=sync` แสดงรหัสคำขอ เหตุผล และเวลา โดยไม่แสดงชื่อผู้ส่ง รายการซื้อ หรือข้อมูลใบเสร็จ ใช้ `nextCursor` สำหรับหน้าถัดไป
- `POST /admin/owner-correction/recover` รับ `correctionId` และ `reason` ภายใต้การยืนยันตัวตนผู้ดูแลเดิม ระบบตรวจสภาพชีตอย่างน้อยสองรอบและรอช่วงที่คำขอเดิมอาจยังทำงานอยู่ หากตรงกับสภาพก่อนแก้พร้อมรายงานเดิม จะส่งงานที่เจ้าของยืนยันแล้วกลับเข้าคิว หากตรงกับผลหลังแก้ จะตรวจความถูกต้องต่อโดยไม่เขียนซ้ำ สภาพผสมหรือพิสูจน์ไม่ได้ยังคงรอตรวจ
- ห้ามข้ามการตรวจด้วยการเปลี่ยนสถานะคิวในฐานข้อมูลโดยตรง และห้ามเปิดเผยรหัสผู้ใช้ LINE หลักฐาน หรือรายละเอียดรายการจริงในบันทึกสาธารณะ

## ข้อจำกัดและเกณฑ์ก่อนเปิดใช้

การย้ายแถวข้ามเดือนหรือเปลี่ยนบัตรจนข้ามรอบบัญชียังพักไว้ให้ตรวจ ไม่ย้ายจริงอัตโนมัติ ใบเสร็จหลายรายการสามารถตรวจการแก้รายละเอียด วันที่ หรือช่องทางต่อได้เมื่อพิสูจน์ข้อมูลย่อยครบ แต่การแก้ยอดหรือหมวดที่ยังจัดสรรรายการย่อยไม่ได้ต้องตรวจเพิ่ม เดือนที่ปิดแล้วหรือยืนยันสถานะไม่ได้ยังพักไว้ รายงานธนาคารเดือนเก่าที่ระบุว่ารอตรวจยังไม่รองรับการแก้ยอดหรือช่องทางชำระอัตโนมัติ Undo และการซิงก์แบบเดิมสำหรับรายการที่แก้แล้วต้องตรวจความเข้ากันได้เพิ่มเติม

มีการเพิ่มตัวกันงานเขียนชีตรายวันชนกันสำหรับงานปกติและงานแก้ไข เมื่อติดตั้ง migration 0027 แล้ว ตัวกันยังทำงานแม้ปิดรับคำแก้ไขใหม่ หากผลเขียนชีตยังไม่แน่นอน งานอื่นจะรอจนพ้นระยะตรวจผล การเปิดฟีเจอร์ต้องติดตั้ง migration 0027 ก่อน มิฉะนั้นงานค่าใช้จ่ายปกติจะซิงก์ไม่ได้ ตัวกันนี้เพียงอย่างเดียวยังไม่พิสูจน์การจองและย้ายแถวที่ปลายทาง รวมถึงการแทรกแถวโดยผู้ใช้ มีโค้ดทดลองจองแถวใน D1 และตรวจแถวปลายทางแบบอ่านอย่างเดียว แต่ยังไม่เชื่อมเข้ากระบวนการย้ายจริง

ก่อนเปิดใช้ต้องพิสูจน์การจองแถวปลายทางร่วมกับผู้เขียนชีตรายวันทั้งหมด ทดสอบการแทรกแถวและป้องกันรายการซ้ำ ยืนยันชีตและสูตรที่ Worker ใช้จริง ติดตั้งและตรวจสิทธิ์ป้องกันชีต ทดสอบครบตั้งแต่ LINE ถึง Worker, D1, Sheets และรายงานด้วยข้อมูลจำลอง รวมถึงสำรอง กู้คืน ทดลอง migration และตรวจคิว/รายการซ้ำหลังเปิดใช้ การป้องกันใน Google Sheets จำกัดผู้แก้ไขทั่วไปได้ แต่เจ้าของไฟล์ยังอาจเปลี่ยนสิทธิ์หรือแก้ช่วงที่ป้องกันได้

ในสำเนาชีตส่วนตัวได้ทดลองแยกช่องหมวดและรายละเอียดที่รายงานใช้ ยอดรายงานย้อนหลังเจ็ดเดือนที่นำมาเทียบไม่เปลี่ยน และการเปลี่ยนช่องแสดงผลโดยตรงไม่เปลี่ยนผลรายงาน ตัวตรวจสูตร สิทธิ์ และแหล่งข้อมูลที่เพิ่มเข้ามายังเป็นเพียงตัวตรวจแบบอ่านอย่างเดียวที่ไม่มีข้อมูลอ้างอิงหรือการเชื่อมต่อจริง ห้ามใช้ผลทดลองนี้ยืนยันว่า Production ปลอดภัย: ต้องตรวจจับคู่ข้อมูลกับ D1 หรือหลักฐานเจ้าของทีละรายการและพักรายการที่จับคู่ไม่ได้ก่อน

หากจำเป็นต้องหยุดฟีเจอร์ ให้ปิดการรับคำแก้ไขใหม่โดยคง Worker ที่รองรับงานแก้ไขและคงตาราง fence รวมถึงประวัติ audit เพื่อให้งานที่ยืนยันแล้วทำต่อหรือพักตรวจได้ ห้ามลบตาราง fence ระหว่างมีงานค้าง หากจำเป็นต้องย้อนกลับไปยัง Worker รุ่นก่อน ต้องระบายงานรุ่นเก่าและตรวจงานที่ยังทำงานอยู่ให้เสร็จก่อนสลับเวอร์ชัน: Worker รุ่นเก่าไม่รู้จักงานหรือกติกา fence ใหม่ จึงอาจไม่ประมวลผลงานแก้ไขที่ยืนยันแล้ว ต้องเตรียมแผน forward-fix และตรวจคิวก่อนสลับ ห้ามนำฐานสำรองเก่ามาเขียนทับธุรกรรมใหม่
