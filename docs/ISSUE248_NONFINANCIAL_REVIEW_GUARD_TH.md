# Issue #248 — ป้องกันการปล่อย workbook เมื่อผล sync พนักงานไม่แน่ชัด

สถานะ: เตรียมตรวจทานและ release เท่านั้น; การ merge หรือ deploy ต้องผ่าน control ของ issue #248 และสถานะ production จริง ไม่ถือว่า PR นี้กู้ระบบเสร็จ

เมื่อ Queue ส่งงาน attendance/payroll หรือ nonfinancial Sheets ที่เป็น `REVIEW` หรือ `COMPLETED` ซ้ำ ระบบต้องไม่เข้าถึง workbook เพื่อเริ่ม notice; งานที่สถานะเปลี่ยนก่อนอนุญาต notice จะปล่อย claim ที่ยังไม่ได้เขียน และหากการตรวจหลังอนุญาต notice (ก่อนเรียก operation) พบสถานะปิดแล้ว จะเก็บ claim เป็น `REVIEW`. ข้อจำกัดที่ยังเหลือ: ถ้าสถานะเปลี่ยนหลังการตรวจนั้นแต่ก่อนที่ operation จะได้ job lease, lease จะไม่สำเร็จและ wrapper อาจจบ notice แล้วปล่อย claim (synthetic counterexample F-B1; แก้แยกใน runtime ถัดไป ยังไม่อยู่ใน PR นี้). การ force reconcile ของ admin ที่เปิดงาน REVIEW/COMPLETED กลับ (F-B2) ก็ยังเป็นข้อจำกัดของ PR นี้. หลัง provider write หาก completion CAS ได้ 0 แถว, acknowledgement หาย หรือ response ขัดแย้ง ระบบเก็บ claim เป็น `REVIEW`, ไม่ resolve failure evidence และไม่ส่ง provider ซ้ำโดยอัตโนมัติ. กรณี job ที่ยังไม่มี outbox, งาน nonterminal, LINE และ terminal hold ยังคงอยู่ในขอบเขตทดสอบ.

ความเสี่ยงที่เหลือ: หาก external D1 writer เปลี่ยน nonfinancial job จาก `COMPLETED` เป็น `REVIEW` หลัง completion CAS สำเร็จแต่ก่อน workbook release ยังมี synthetic counterexample ที่อาจปล่อย claim และ resolve failure ได้. ไม่พบ normal product path ที่ยืนยันการเปลี่ยนดังกล่าว และไม่มีหลักฐานว่าเหตุการณ์นี้เกิดใน production; Owner ยอมรับ residual risk นี้ใน session. ไม่อ้าง positive writer freeze หรือ provider outcome ที่ยังไม่ทราบ. D1 subrequest สูงสุดและผลต่อ throughput ใน production ยังต้องตรวจ.

หลักฐาน local สำหรับ code patch ที่ review: focused 103 PASS / 0 FAIL / 0 SKIP; typecheck ผ่าน; suite เดิมรันด้วย jq และ test concurrency 2 ได้ 1,210 PASS / 0 FAIL / 6 SKIP; Wrangler ของ repo `deploy --dry-run` ผ่าน. `npm run check` ที่ default concurrency ได้ 1,206 PASS / 4 FAIL / 6 SKIP โดย 4 workflow fault-injection subprocess คืน status null ใกล้เวลาจำกัด; ทั้ง 4 ผ่านเมื่อรันแยก. อย่ารายงาน command แรกว่าผ่าน. ผล CI และ independent review ให้ผูกกับ PR head จริง.

ไม่มี migration หรือ config change ใน patch. ก่อน release ต้องตรวจ claim, REVIEW jobs, Queue/Cron, Worker version, provider outcome และ gate ตาม incident control จริง. หาก deploy outcome ไม่แน่ชัด หยุดและตรวจ provider; ห้าม replay หรือ rollback โดยเดาสถานะ. หลัง release ต้องติดตามงานใหม่, failure/REVIEW และกระทบยอด attendance/payroll/ค่าใช้จ่ายตาม issue #248.
