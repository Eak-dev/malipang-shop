# ต้นแบบกู้ marker ของรายการส่วนตัวเดือนตุลาคม

โค้ดนี้เป็น candidate ที่ปิดโดยค่าเริ่มต้น และยังไม่ใช่คำสั่งใช้งาน production การ deploy และเปิด flag ต้องตรวจชุด migration ทั้งหมด การกั้น editor และการระบาย Worker/คำขอ Google เก่าให้เสร็จก่อน ช่วงรออย่างน้อย 15 นาทีเป็นเพียงเงื่อนไขขั้นต่ำ ไม่พิสูจน์ว่าคำขอเก่าหยุดแล้ว

เมื่อ marker ที่จองไว้ไม่ปรากฏ การตรวจใช้ Google metadata search ตาม ID แบบอ่านอย่างเดียวสองครั้งและอ่านทั้งตารางระหว่างกัน จากนั้นเทียบรายการจาก D1, ID ที่จองใน registry, metadata ในทุกแถวและค่าทั้งแถวเป้าหมาย หากหลักฐานไม่ตรงหรือไม่ครบให้คง REVIEW เสมอ การส่ง marker ใหม่ใช้ action ที่อนุมัติแยก ตรวจซ้ำหลัง OAuth และบันทึก DISPATCHED พร้อม audit ก่อนส่งเพียงครั้งเดียว หากผลตอบรับหรือการอ่านกลับไม่ชัดเจนให้คง REVIEW และห้าม replay

`DELETE_WRONG_ROW` ปิดทุกทาง รวม action ที่อาจมีอยู่ก่อนแล้ว: การจอง metadata ID ใน D1 ไม่พิสูจน์ว่า marker บน Google ถูกสร้างโดยระบบนี้ การลบต้องรอหลักฐาน provenance ที่เชื่อถือได้และรีวิวแยก

Recovery ของ action ที่ค้าง REVIEW จากคำขอ remediation เองยังไม่พร้อม: schema ปัจจุบันตั้งใจบล็อก action ใหม่และการปลดล็อกทั้งชีตไว้ ต้องมีการตรวจ provider/source ใหม่ แยกการอนุมัติ บันทึก audit และยืนยันการระบายคำขอจริงโดยไม่ replay ก่อนใช้งาน production

โค้ด `historicalEnrollmentIntegrity` รุ่นนี้ต้องพบ migration 0055 และ trigger ที่ตรงครบ หากปล่อยโค้ดก่อน schema จะ fail closed และพักงานที่พึ่ง guard นี้ การ rollback Worker หรือ schema ต้องคงการกั้น writer และพิสูจน์สถานะ REVIEW ค้างก่อนปล่อยงาน
