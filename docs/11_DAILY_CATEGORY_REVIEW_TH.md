# การเสนอเปลี่ยนหมวดจากชีตรายวัน

คอลัมน์ V เป็นช่องเสนอเปลี่ยนหมวด ไม่ใช่หลักฐานว่า D1 เปลี่ยนแล้ว ผู้แก้ชีตเลือกค่าจากรายการ จากนั้นเจ้าของที่ยืนยันตัวตนแล้วพิมพ์ `ตรวจหมวด` ใน LINE เลือกคำขอ และกดอนุมัติหรือไม่อนุมัติ คำขอแสดงยอด วันที่ หมวดเดิมและหมวดที่เสนอ หากแถวหรือข้อมูลเปลี่ยนก่อนอนุมัติ ต้องตรวจคำขอใหม่

หลังอนุมัติ ระบบบันทึกผู้อนุมัติและประวัติ เปลี่ยนหมวดใน D1 แล้วส่งงานซิงก์แบบมีประวัติไปยัง `V52_EXPENSE_RAW` และ `รายละเอียดการซื้อ` เฉพาะคอลัมน์หมวด ไม่เปลี่ยนยอด วันที่ หรือบัตร รายงานที่อ้างอิงข้อมูลเหล่านั้นจะเปลี่ยนตามสูตรของรายงานนั้น การซิงก์ที่ยังไม่เสร็จต้องตรวจสถานะงาน ไม่ถือว่าเสร็จเพียงเพราะเจ้าของกดอนุมัติ

ระบบเชื่อมรายการเก่าเมื่อระบุรายการได้ตรงกันและไม่กำกวมเท่านั้น แถวที่ไม่มีรายการ D1 หรือข้อมูลไม่ตรงจะไม่ถูกสร้างหรือเปลี่ยนโดยอัตโนมัติ หากไม่อนุมัติ ค่าใน D1 คงเดิม ผู้ใช้ควรคืนช่องในชีตเป็นหมวดเดิม คำขอเดิมจะไม่ถูกสร้างซ้ำจนกว่าจะคืนค่า

## การเตรียมใช้งาน

ปิดค่า `DAILY_CATEGORY_REVIEW_ENABLED` เป็นค่าเริ่มต้น การใช้งานจริงต้องผ่านการทดสอบ UAT และแผน Production Change แยกต่างหาก ต้องลง migration 0021 ก่อนโค้ดใหม่ เพราะตัวประมวลผลงานชีตอ้างอิงตารางใหม่แม้ยังปิดฟีเจอร์ ตรวจสำรองและทดสอบการกู้คืนตาม AGENTS.md ก่อน migration

หลังได้รับอนุมัติสำหรับการเปลี่ยนระบบจริง ผู้ดูแลใช้ `POST /admin/category-review/bootstrap` ผ่านการยืนยันตัวตนของ admin เพื่อเชื่อมข้อมูลเป็นชุด ชุดละไม่เกิน 20 รายการ ทำซ้ำจนไม่มีรายการที่พร้อมเชื่อม ตรวจจำนวนข้อขัดแย้งและแก้เป็นรายกรณีโดยไม่เดา จากนั้นจึงเปิด `DAILY_CATEGORY_REVIEW_ENABLED=true` และใช้ `POST /admin/category-review/dropdown` เพื่อเพิ่มรายการเลือกและหมายเหตุ ฟีเจอร์ที่เปิดแล้วตรวจรายการใหม่และเสนอคำขอเป็นระยะด้วย scheduled maintenance หรือเมื่อเจ้าของพิมพ์ `ตรวจหมวด`

## การตรวจและย้อนกลับ

ทดสอบเจ้าของและผู้ไม่มีสิทธิ์ เลือกหมวดใหม่ เปลี่ยนซ้ำก่อนอนุมัติ กดซ้ำ แทรกแถว และจำลอง Sheets/LINE ล้มเหลว ตรวจ D1, audit, sync_jobs, failed_jobs, ชีตข้อมูลดิบและรายละเอียดสินค้าทุกครั้ง หากพบปัญหา ปิด flag เพื่อหยุดการรับคำขอใหม่ ตรวจและจัดการงานซิงก์ที่ค้างอย่างระมัดระวัง และนำ dropdown ออกหากจำเป็น การปิด flag ไม่ย้อนรายการที่อนุมัติแล้วหรือยกเลิกงานซิงก์ที่สร้างไว้ ควรแก้ไขย้อนกลับผ่านกระบวนการที่มีประวัติหลังตรวจยอดและผลกระทบ

ยังต้องทดสอบร่วมกับ Google Sheets และ LINE ในสภาพแวดล้อม UAT ที่ได้รับอนุญาต ตรวจความสามารถรองรับจำนวนรายการจริง และตรวจผลรายงานปิดเดือนก่อนเปิดใช้งานจริง
